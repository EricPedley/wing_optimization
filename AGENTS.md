# SimITL playback + in-game experiments

- Use the submodule build `SimITL/build/linux/install/bin/simitl-playback` — the loose checkout at `~/code/SimITL` is stale (no eRPM telemetry emulation). Always run it with cwd `SimITL/tools/simitl-playback` so `config/` and `test.bin` resolve.
- `test.bin` is the quad eeprom the sim loads/saves. pr0p per-quad `.bin` files are the same format — copy `~/.config/unity3d/sigsegowl/pr0p/config/quad/<q>.bin` to `test.bin` to fly that tune headlessly. The file is 32768 B but the build wants ~224724 B: load is partial (`failed to load ... 32768 < 224724` is a warning, not fatal — loaded fields still apply; missing tail = defaults).
- Blackbox logging: the `.bbl` is only written if the loaded eeprom has blackbox enabled. Game bins have it on; a freshly generated stock `test.bin` does NOT (no `.bbl` is produced at all). If `blackbox.bbl` is missing, check the eeprom first.
- MSP over websocket: connect `ws://localhost:5761` while the sim runs (`i -no -ns` idle mode works). Useful commands: 90 motor config, 92/93 filter config get/set, 94/95 PID advanced get/set (last 4 bytes = tpa_mode/tpa_rate/tpa_breakpoint), 112/202 PID get/set, 210 select pid profile (0-3), 250 eeprom write. Pattern: read payload -> patch bytes -> write back -> 250 -> restart the process.
- PID profiles: `hq-65mm-micro.bin` (and every variant .bin) carries 4 profiles — 0=stock, 1=damped P26/D54 P29/D60, 2=over-damped P20/D44 P22/D49, 3=P1 gains + TPA mode PD 40% @1350. Switch in-game via configurator Profiles tab, or mid-flight headlessly via MSP 210.
- ghost.json rcData is normalized [-1,1] and channels are RATE commands in acro — a held pitch value tumbles the quad, it does not hold a tilt. To build airspeed use a brief pitch-rate kick then rc1~0.
- Playback outputs land in cwd: `blackbox.bbl` (decode with `~/code/betaflight-rl-wrapper/analysis/blackbox-tools/obj/blackbox_decode`), `quadstate.csv`. `bb` replay mode needs the decoded CSV to have its column header NOT on line 0 (the `readBlackboxFile` parser treats `colHeaderLine==0` as not-found) — prepend one `H ...` line first.
- Oscillation metrics that worked: kick-then-hold ghosts (brief rate kick, then hold) and compare 15-120 Hz filtered-gyro band energy in the HOLD windows. A continuous-random-kick ghost is dominated by the maneuver response itself and does not isolate the mode.
- Game selector gotcha: a quad json whose `motor`/`propeller`/`battery` names do not match a component json `name` in the same config dir is silently dropped from the selector. Quad `model` must match a `.glb` filename in `pr0p_mods/`.
- Vibration findings (2026-09): the micros' shake is a marginally-stable rate-loop mode (~20-30 Hz), not injected noise at the wrong frequency. Linear model (rate_plant + real delay chain: 2 ms ESC + 100 Hz pwm LPF + BF biquads): PM 36/29deg for 65/75mm vs 45deg 51mm vs 49deg 5-inch, degrading with throttle — matches the in-game <40 Hz band and the "oscillates at full throttle + stick input" signature. Fixes ranked by hold-window 15-120 Hz energy on the loud config: stock tune 2.86; retuned profiles ~1.4-0.02; halved motorR / I0*0.3 ~0.01-0.02 (actuator speed is the dominant fix). Lower gyro LPF makes it WORSE (more lag). Stock eeprom carries TPA mode D-only 65%@1350 which removes damping at throttle. `rate_plant.loop_with_filters` models BF lowpasses as 2nd-order Butterworth biquads — a first-order model overestimates PM by ~13deg at ~16 Hz crossover and led to one divergent tune (P33/D110) in-game.

# SymForce embedded MPC

- `multirotor/optimal_control_symforce.py` mirrors `optimal_control.py`/`four_motor_plant.py` in symengine. `RiccatiMPC` solves the same tracking+slew QP via backward Riccati on the slew-augmented state: bit-exact vs OSQP when unconstrained, clip-projection when bounds are active. `generate()` emits templated C++ to `multirotor/symforce_mpc/generated/` (substep, substep_jac, plant_step, riccati_step, forward_step, collective_thrust_jac, mpc_constants). Regenerate after changing the quad config or weights: `uv run python -m multirotor.optimal_control_symforce` (takes several minutes, dominated by plant_step).
- `multirotor/symforce_mpc/quad_mpc.h` is the fixed-size driver: init() composes per-substep jacobians into A,B (chain rule over 20 substeps), update() runs one Riccati backward + clipped forward pass per tick. No heap, no real Eigen needed (eigen_shim/). Per-tick cost ~0.4 ms on x86. Gotchas: generated funcs must not alias in/out buffers; u0 is the first forward_step stage.
- Bridge support: `simitl-controller-bridge` accepts `"controller":"mpc"` (requires `mode:"external"`, refuses mismatched quad via `kQuadKey`). Rebuild with `make simitl-controller-bridge` in `SimITL/build/linux` (run `cmake .` first if includes changed). Drive it via `run_simitl_case(..., controller="mpc-embedded")`. Measured on roll step, ideal state: embedded 6.95 / python-mpc 7.63 / bf 8.06 deg/s RMS.
- In-firmware flight mode: `sim_mpc.cpp` (betaflightext target/simITL) runs the same generated MPC inside `pwmCompleteMotorUpdate` — `BOXMPC` ("MPC CONTROL", permanentId 56, appended at the end of `boxId_e` so no enum shifts or PG bump) on an AUX channel switches the rate loop to MPC live, `trackCommands` resyncs the queue/slew state while inactive so the handoff is bumpless, and between 2 ms solves it rewrites motorsPwm to hold the command (the PID task keeps running underneath; blackbox `motor[]` logs show the PID's values, not the applied MPC ones). Feedback = filtered gyro + `getSetpointRate` + DShot eRPM; the ESC filtered-PWM state is estimated locally (queue head through a 100 Hz PT1 model). Throttle stick maps to a collective-thrust target via a quadratic map normalized to `kHoverStick` (= trim command, so stick-at-hover-throttle gives coll=1); full stick requests `kCollMax` (feasible collective at u=0.95, ~4.2x hover). The driver bisects the linearized collective row against the generated nonlinear `Collective()` — thrust is convex in rotor speed so the linear row alone undershoots ~30% at max throttle. A plain secant/step iteration DIVERGES there (oscillates between ~1.1 and ~0.55 pwm) — keep the bisection. Read throttle from `rcCommand[THROTTLE]` (post-channel-map) not raw rcData. Solve is ~20us in firmware: the Riccati K_k and the affine feedforward map are state-independent, so `init()` probes the 7-dim target rhs (bias, ref, coll) through one backward pass each and bakes `G_[sched][stage][4][7]` — per tick is a 4x7 matvec + clipped rollout (K/f are NOT recomputed per tick). Gains are gain-scheduled: `linearize()` runs at kNumSched=3 equilibria (kSchedX/U, omega ~1704/2755/3412 rad/s) and tables interpolate by mean measured rotor speed — the micros' marginal rate mode loses margin at high throttle with hover gains. The g+P*dz disturbance correction is folded into the bias columns of G. Bake uses slew_weight=0.1 (S>0 damps the clipped-rollout limit cycle at saturation; slew=0 bang-bangs). Collective target lam may go NEGATIVE (below-hover thrust needs it — do not clamp to 0); it's bisected on the nonlinear Collective() then capped where u_ref hits bounds (0.5 dev up, idle-floor down). Mixer semantics are STRUCTURAL, not post-processing: the QP input is v = 3-dim differential (kMixV, M'M=4I); applied u = clip(m*1 + M*v) where m = mean(u_ref) is pinned to the collective target exactly like BF's mixer pins mean(motor)=throttle. Regen kernels use m=3 (riccati_step n=15 m=3 -> z=18 = [x15; v_prev3]). Two traps that each cost a debugging cycle: (a) the slew tail must store the EFFECTIVE applied differential v_eff = M'(u_app - m)/4, NOT the commanded v — under clipping a commanded-v tail becomes a phantom slew reference that bang-bangs the motors (symmetric rpm, railed alternating pwm); (b) probe passes must fold BOTH constant affine terms into geff = g + P*a — disturbance dz on rate rows AND the pinned m into the queue-tail slots (a[kStates-4+i] = m_j). Schedule variable wbar_ is low-passed (0.05/tick) — raw eRPM jitter otherwise wanders the gain tables = low-freq nonperiodic wobble. Observer baked with noise_dps=3 (slower bias, less propwash-noise chasing). Disturbance robustness comes from a baked Kalman bias observer (`kBiasGain` in `mpc_constants.h`): the rate innovation integrates into `bias_` (units = scaled rate/s, clamp 500); a 25%-damaged motor holds ~5 deg/s rate RMS at hover collective, ~15 saturated (BF PID ~10). Bridge accepts `prop_damage[4]` for disturbance tests; `mpc_fw_bias` is in telemetry. In-game: Modes tab shows "MPC CONTROL" — assign it to an AUX (configurator over MSP `ws://localhost:5761`); a same-range ARM switch must exist too. Expect a brief motor punch on activation while rotors converge to the model's hover state. The bridge sets it programmatically on rc[5] via `configureBridgeArming`; `run_simitl_case(controller="mpc-switch")` flips it at t=1 s. Firmware version bumped to 12.1 (`FC_VERSION_PATCH_LEVEL`) so the configurator shows SimITL 12.1 when the MPC build is loaded. **Deploy to the game**: `make` in `SimITL/build/linux` produces `src/libSimITL.so`; the game loads `~/programs/pr0p/pr0p_Data/Plugins/libSimITL.so` — copy it over manually (stock backup is `libSimITL.so.stock`). `make` alone does NOT update what the game loads.
